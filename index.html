~/caso-estudio

Caso de Estudio: AlkeWallet2

AlkeWallet2 es una billetera digital nativa desarrollada en Kotlin para Android, que demuestra la aplicación de patrones modernos de arquitectura (MVVM + Repository), persistencia local resiliente y buenas prácticas de testing.

Descripción

Aplicación móvil nativa para la gestión de finanzas personales. Permite autenticación con JWT, visualización de saldo en tiempo real, historial detallado de transacciones, envío e ingreso de dinero, y perfil de usuario con cierre de sesión seguro. Arquitectura MVVM con ViewBinding, LiveData y Repository como única fuente de verdad.

Desafío Principal

Superar el acoplamiento de una arquitectura MVC anterior, garantizando persistencia offline-first y estabilidad del ciclo de vida. Resolver la baja del backend en AWS sin detener el desarrollo. Evitar transacciones duplicadas. Adaptar renderizado a Edge-to-Edge (Android 15+).

Solución

Implementé flujo unidireccional y reactivo con LiveData<WalletResult<T>>. Centralizé datos en WalletRepository como SSOT. Para resolver caída del backend, diseñé servidor mock en Node.js + Express y suite de tests con MockWebServer. Introduje filtro de integridad por remoteId para evitar duplicados. Listeners programáticos de WindowInsetsCompat.

Stack Técnico

  • Lenguaje: Kotlin 1.9+/2.0+
  • Arquitectura: MVVM + Repository
  • UI: ViewBinding, Material Design 3, Picasso
  • Persistencia: Room 2.7.0-alpha13, SQLite
  • Red: Retrofit 2.9.0, Gson
  • Testing: JUnit 4, Mockito, MockWebServer
  • Build: Gradle (Kotlin DSL), Version Catalogs

Aprendizajes Clave

  • Ciclo de vida y reactividad: Estado desacoplado previene fugas de memoria
  • Datos híbridos: Coordinación segura entre Room y REST
  • Resiliencia: Desacoplamiento de API mediante DTOs y testing
  • UI moderna: Insets programáticos para Edge-to-Edge

Métricas de Impacto

  • ✅ 100% ViewBinding: 6 Activities, 2 Fragments, Adapters
  • ✅ 11 pruebas JVM: 100% éxito automático
  • ✅ 0 duplicados: Filtro remoteId garantiza integridad
  • ✅ 8 pantallas: Flujo E2E completamente funcional
  • ✅ Resiliencia operativa: MockWebServer + Mock API

Habilidades Aplicadas

  • MVVM, Repository Pattern, Factory Pattern
  • Room ORM, DAOs, consultas reactivas
  • Retrofit, Gson, JWT simulado
  • Unit tests (JUnit), Integration tests (MockWebServer)
  • Gestión de back stack segura
  • WindowInsetsCompat, Material Design 3

¿Por qué este proyecto?

La evolución de MVC a MVVM demuestra transición de código funcional a arquitectura profesional. Refleja tres ejes críticos: (1) Adopción de estándares modernos (MVVM + Repository), (2) Capacidad de resolución ante bloqueos (caída de AWS → MockWebServer), (3) Atención a detalles de producción (Edge-to-Edge, anti-duplicados, limpieza de sesión). Este es el proyecto que mejor refleja mi crecimiento técnico.
